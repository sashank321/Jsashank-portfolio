## 2025-09-25 - [Add Next.js Security Headers Compatible with Animation Libraries]
**Vulnerability:** The application was missing critical security headers like Content-Security-Policy (CSP), X-Frame-Options, Strict-Transport-Security, and others. This could leave the static application susceptible to attacks such as Clickjacking or Cross-Site Scripting (XSS).
**Learning:** When configuring CSP in Next.js applications that utilize advanced animation libraries like GSAP or Framer Motion, strict CSPs without `'unsafe-inline'` and `'unsafe-eval'` break animations because these libraries rely heavily on inline styles for performance and evaluation for dynamic variables.
**Prevention:** Always verify that security policies applied via `next.config.ts` are balanced with the functionality of core frontend libraries by allowing `'unsafe-inline'` for styles and `'unsafe-eval'` and `'unsafe-inline'` for scripts when animation libraries necessitate it, instead of applying a blanket strict policy.
