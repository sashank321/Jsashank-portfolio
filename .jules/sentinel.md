## 2025-02-28 - CSP with Static Rendering and UI Libraries
**Vulnerability:** The application was missing crucial security headers, including Content-Security-Policy (CSP), leaving it susceptible to XSS, clickjacking, and other injection attacks.
**Learning:** Due to Next.js limitations with static rendering and `nonce`-based CSPs, enforcing strict CSPs disables static export and caching. Furthermore, animation libraries used heavily in this codebase (GSAP and potentially Framer Motion) require `'unsafe-eval'` and `'unsafe-inline'` for scripts and styles. Implementing a strict `nonce`-based CSP would require refactoring the app to dynamic rendering, which hurts performance in a static portfolio context.
**Prevention:** For static Next.js sites with heavy animation dependencies, set a baseline CSP in `next.config.ts` using `unsafe-inline` and `unsafe-eval` instead of nonces to maintain static generation. Avoid removing these directives unless an alternative like SRI is feasible and well-tested with the UI libraries.
