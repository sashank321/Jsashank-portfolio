## 2024-05-18 - Missing Security Headers in Next.js Setup
**Vulnerability:** The application was missing basic security headers (like Content-Security-Policy, X-Frame-Options, X-Content-Type-Options), which leaves the site vulnerable to XSS, clickjacking, and MIME-sniffing attacks.
**Learning:** Default Next.js setups do not come with strong security headers out of the box. Next.js applications need to have these explicitly configured in `next.config.ts`, especially important given the rich client-side hydration context which is a high-value target for XSS. Additionally, strict CSPs often need careful tuning with 'unsafe-inline' and 'unsafe-eval' for Next.js to function alongside animation libraries like GSAP and Framer Motion.
**Prevention:** Always include a baseline set of security headers via the `headers()` async function in `next.config.ts` for any new Next.js project. Ensure CSP allows necessary directives for standard React/Next.js functioning without completely compromising protection.
